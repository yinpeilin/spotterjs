```powershell
npm ci --ignore-scripts --dry-run --audit=false --fund=false
```

The error is `npm error Invalid Version:`. The npm stack fails in Arborist's
`Node.canDedupe` while placing `@spotterjs/node-linux-x64-gnu@1.1.1`.

Related evidence:

- Root [package.json](../../../package.json), lines 81–83, still pins
  `@spotterjs/core@1.1.0`, `@spotterjs/plugin-android@1.0.5` and
  `@spotterjs/plugin-ocr@1.1.0`. These differ from the workspace versions.
  The root dependency entries in [package-lock.json](../../../package-lock.json)
  also retain the old versions.
- The two nested native optional entries at lockfile lines 46–50 contain only
  `optional: true`, without version or resolution metadata. These incomplete
  entries predate this diff; they have not been established as the sole cause.
- `npm ls` passes against the existing installation. That does not establish
  that a clean checkout can install successfully.

Tasks and acceptance:

- [ ] Align the three root `@spotterjs/*` development dependencies with the workspaces.
- [ ] Identify the invalid version source, regenerate and inspect the lockfile
  through normal npm resolution, and avoid manually assembling dependency entries.
- [ ] Run `npm ci` in temporary clean checkouts under both CI's Node.js 20 and
  the current Node.js 24 environment. Record the npm versions and results.
- [ ] Confirm that workspace packages resolve to the intended versions and
  native optional packages match the loader, then rerun builds and unit tests.

### T2 · P2 · Preserve Structured Diagnostics in CLI Results

`summarizeContext()` in [results.ts](../../../packages/cli/src/tools/results.ts),
lines 36–44, keeps only the first 12 object keys and replaces objects at depth
two or deeper with `"[object]"`. The new diagnostics exceed these limits.

A pure-function reproduction extracted from the current source, using the
same diagnostic shape as the Rust output, confirms:

- `serde_json` has no `preserve_order` feature enabled and emits alphabetically
  ordered keys. The 12-key limit removes `timestampMs`, `windowStation` and
  `windowStationIsInteractive`.
- `foregroundWindow` becomes `"[object]"`. Each `{ field, error }` item in
  `errors` also becomes `"[object]"`.
- `initialError`, `retryAttempted`, `retryStage` and `retryError` remain present.
  The error message also retains some diagnostic evidence.

Tasks and acceptance:

- [ ] Define bounded diagnostic output that preserves the actual window station,
  foreground window, diagnostic query failures and recovery-stage fields.
- [ ] Keep reasonable size limits and cover more than 12 keys, nested objects,
  `null` fields and diagnostic query failures.
- [ ] Add regression coverage through the native error payload, TypeScript
  wrapper and CLI JSON, asserting stable codes and required diagnostic fields.
- [ ] Make those fields directly readable from CLI error JSON without parsing
  the human-readable `message`.
